# Домашнє завдання (слайд 48)

## 1. Напишіть serverless-функцію з HTTP-тригером

Функція приймає JSON і повертає оброблений результат (валідація або перетворення).
Візьміть `cmd/webhook` за основу, але **змініть предметну область** (наприклад,
нормалізація запису про читача, розрахунок штрафу за прострочення).

Вимоги: щонайменше дві фікстури в `events/` (валідна й невалідна); `go test`
проходить; 400 для поганого вводу, не 502; клієнти й конфігурація — на рівні пакета.

## 2. Згенеруйте Terraform і проаналізуйте його рядок за рядком

1. Згенеруйте конфігурацію ШІ за промптом із `docs/ai-prompts.md`.
2. Заповніть таблицю:

| Ресурс / рядок | Що створює | Ризик | Чи змінили? Чому |
|---|---|---|---|
| | | | |

3. Виконайте `terraform plan` на Floci (`make plan-tf`) і додайте висновок щодо того,
   чого ви **не очікували** побачити.

## 3. Нотатка «serverless чи постійний сервер» (5–7 речень)

Для **вашого pet-проєкту**: коли б ви обрали serverless, а коли постійний сервер?

Орієнтири для міркувань: профіль трафіку (піковий чи стабільний), довготривалі
з'єднання, чутливість до холодного старту, вартість за стабільного навантаження,
операційна зрілість команди. Згадайте, чи змішали б ви обидва підходи (слайд 28).

```
Мій проєкт: …
Я б обрав …, тому що …
Але для … використав би …, тому що …
Ризики: …
```
